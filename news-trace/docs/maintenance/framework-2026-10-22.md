# 2026-10-22 执行框架

类型：**维护记录**。[流程](../workflows/edition-pipeline.md) · [数据约定](../contracts/edition-v1.md)

实现了统一入口 `scripts/edition.py`：初始化空白一期、检查结构与证据引用、生成待填复核模板、在通过复核后生成 Markdown、英文邮件正文与附件包。内部模块按数据、校验、渲染分开，均只依赖 Python 标准库。

检查包括输入时间、入选集合、聚类标识、已报道事件、逐条证据、信息链、发现覆盖、英语字段、复核时效与文件哈希。P1 提示必须填写读者可见说明。正文直接引用主张记录；完整版与邮件用同一事件集合和证据。交付只到 `prepared_not_sent`，再次构建拒绝覆盖已有成果。

修复了 BBC／新华社校验器：现在遵守输入快照的截止时间与回看窗口，不再使用完成时间倒推固定 72 小时。补充了无时区时间和非正窗口检查。

历史三期的[框架就绪检查](../../diagnostics/2026/10/22/framework-readiness.json)都未通过新发布门槛，因为缺少结构化编辑输入及逐条证据记录。这个结果不能证明旧稿事实错误，也不能证明旧稿正确；真正的原文回查仍在待办。没有把旧资料自动标为已核验。

测试使用明确标注的合成新闻，覆盖修改后复核失效、缺失证据、转载来源、未披露 P1、双语渲染、附件一致性、重复构建、HTML 转义及历史窗口回归。真实采集、邮件发送与定时调度需要后续现场验收。
