# 邮件交付

类型：**规则文件**。[每日流程](daily-brief.md) · [简报档案](../../editions/README.md)

1. 以已核验的一期简报为依据，写英文邮件正文：概述、各独立事件的摘要及原文链接，可适度精简；保留事实归属和重要不确定性。
2. 按产品类型命名：每日简报使用 `codeX整理的每日新闻简报｜YYYY-MM-DD`（要求全英文时用 `codeX Daily News Briefing`）；专题追踪使用 `codeX Special Report | TOPIC | YYYY-MM-DD` 或 `codeX Topic Tracker`，不能套用 Daily 标题。重发修订版时明确标注。收件人按用户本次或适用的既有授权确定；历史收件地址不等于自动定时发送授权。
3. 独立附上完整版 Markdown 或 PDF；把输入快照、候选台账、必要复核说明与清单打成资料包。正文不能只写附件介绍或技术统计。
   专题使用其实际研究证据与阅读指南，不伪造每日采集快照。发送前核对 MIME 附件清单、ZIP 解压与相对链接；必要说明随附件布局提供，不能只在本地补链。发送后保留原始字节与哈希。专题归档路径见[记录约定](../contracts/topic-records-v1.md)。
4. 在本期 `delivery/` 保存邮件正文与附件。资料包清单写清内容和限制，不包含缓存、重复文件或不必要中间数据。
5. 用户授权发送后通过 Gmail 接口发送；记录返回的邮件 ID、收件人、标题和发送状态。标记 `SENT` 证明已发送，不证明收件人已阅读。失败或状态不明时先查询，避免重复发送。
6. 检查附件完整性，清理 `tmp/`。保留已发送版本；更正需另存并明确说明。

2026-10-03 的更正版已在对话中得到 `SENT` 回执，但本地未保存完整邮件正文及发送回执文件。后续交付按上述规则留档；不以新写文件冒充当日原件。

结构化一期可用 `python3 -B scripts/edition.py build ISSUE` 生成以上正文及附件，详见[完整框架](edition-pipeline.md)。读取 `delivery/manifest.json` 并核对哈希后，才能使用指定材料发送；`prepared_not_sent` 不是已发送回执。
