# 专题追踪流程

类型：规则文件。[编辑纲领](../standards/editorial-charter.md) · [记录约定](../contracts/topic-records-v1.md) · [专题目录](../../topics/README.md)

## 1. 带着问题检索

接续最近一期，确定本期 3–6 个必须回答的问题和截止时间。分两条线查找原文：**进展线**追踪事件、谈判与执行；**解释线**查数据、制度与深度报道。按问题补齐来源和相反证据，不以媒体数量衡量覆盖。

## 2. 先证据，后正文

先在 `evidence.md` 记录关键主张、出处、原文位置和支持范围，再写报告。背景可复用；决定“当前状态”的事实须本期重新核实，失败则注明最后核实时间并收窄结论。重大责任、争议数字和强因果判断优先找独立证据或原始文件。访问记录沿用[访问等级](../../skills/news-briefing/references/access-levels.md)。

## 3. 把变化讲清楚

主时间线只列实际事件；报道与核查时间留在证据记录。措施按**宣布 → 资金 → 执行 → 效果**标记已证实阶段。分析各方诉求及内部差异；对重要解释比较支持证据、反证和缺口，明确判断强弱。

## 4. 分层写作

英文正文依次呈现：本期新增／修正、事件时间线、各方立场、措施落实、分析与待解问题。精选深度阅读可单列指南，每篇简述价值和局限。引用与辅助材料复用主证据记录，避免多份台账重复维护。

## 5. 从结论反查，再交付

完成草稿后，按重要性逐条从结论返回原文，检查是否把宣布当落实、采访当民意、指控当事实、转载当独立来源、旧资料当最新进展。简记复核结果：**P0 修正后交付；P1 解决或披露；P2 留待跟进。**

按[邮件流程](email-delivery.md)完成已授权交付，并核对正文、附件、链接和发送回执。保留已发版本，更新专题首页的新增事实和开放问题；只有重大转折才重写总体判断。

当前为人工／agent 编辑流程。验收看核心问题是否得到回答、结论是否可反查、本期增量是否明确。
