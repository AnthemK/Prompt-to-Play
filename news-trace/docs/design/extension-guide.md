# 当前结构与扩展位置

[首页](../../README.md) · [完整设计稿](overview.md) · [待办](../../memory/TODO.md)

当前实现是标准库 Python 脚本与 agent 编辑流程：`配置 → 采集快照 → 核验和事件取舍 → 简报 → 邮件交付`。程序完成采集及部分检查，事件合并、事实核验和摘要仍需要编辑判断。目录整理不等于这些环节已自动化。

| 要扩展的能力 | 首先改哪里 | 如何验收 |
| --- | --- | --- |
| 新增媒体或栏目 | `config/sources/`；研究依据放 `docs/research/` | ID 唯一，日期可靠，试跑可重复，证据等级清楚 |
| 新站点解析 | `scripts/collect.py`、`scripts/article_probe.py` 与 `tests/` | 使用合成样例做离线回归，再抽查原站 |
| 断言级溯源 | 每期 `evidence/`，配套校验程序 | 每项主张对应原文位置、时间与证据等级 |
| 新交付渠道 | 本期 `delivery/`，对应 `docs/workflows/` | 正文、附件、明确授权与发送结果可核对 |
| 定时运行 | 稳定现有手动流程后再加调度入口 | 窗口明确、失败可见、重试不覆盖或重复发送 |
| 可展开阅读界面 | 读取 `editions/` 与 `memory/` 的正式数据 | 不另存一套互相漂移的事实来源 |

程序规模扩大后再将解析器或渲染器拆成模块包。现在保留可直接运行的 `scripts/`，统一目录定位放 `scripts/paths.py`，避免每个程序各自猜测项目位置。

添加新的一级目录前先判断是否属于现有类别；只为已有内容建立目录。当前结构、配置与证据之间的链接可用 `python3 -B scripts/check_layout.py` 检查。
