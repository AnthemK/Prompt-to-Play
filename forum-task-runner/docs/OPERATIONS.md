# 运行、备份和恢复

## 日常运行

正式服务端口 8924；不要同时手动启动第二份服务。自启动配置位于 `~/Library/LaunchAgents/local.forum-task-runner.plist`，指向当前项目和 Node 可执行文件，移动项目或删除该 Node 运行时后需要重新安装自启动。

启动链接见 `.data/service.log`，其中含管理令牌，不要分享。管理页的记录是任务是否成功的依据；“已保存登录态”只表示存在存储对象，不保证仍有效。暂停单站任务请在管理页点击暂停计划，不必停整个服务。

Mac 删除自启动：`npm run autostart:remove`。恢复：`npm run autostart:mac`。电脑睡眠或关机时不会执行。服务使用自然日/自然周去重，没有后台 AI 或云端调度。

## 备份

先停止服务（`npm run autostart:remove`，手动启动的服务则 Ctrl+C），再复制整个 `.data/accounts/<account>` 到安全位置。数据库与 `vault.key` 必须一起保存。不要在服务运行中只复制 SQLite 主文件，未合并的数据可能仍在 WAL 文件中。

备份全部账号可复制整个 `.data`；备份含登录凭证、管理日志，不应进 Git 或发给他人。单账号恢复时，停止服务，将备份恢复到同名账号目录，确保不存在其他账号持有相同任务 ID，再启动服务。恢复后可能需要重新登录。

## 本次 v1 → v2 迁移

旧版所有任务在 `.data/tasks.sqlite`。新版首次启动在持有服务锁的情况下，解密旧配置及登录态，将任务和历史按 account 分配，使用各自新密钥重新加密。先写临时目录，再提交完整账号目录。旧数据保留到 `.data/backups/legacy-v1`，不参与日常运行。

若迁移失败，保留旧数据，检查错误，不删除数据库或密钥。若迁移提交后中断，`accounts/.complete` 标记用于识别已提交的数据；旧根目录文件可能尚未归档，但不再被读取。不要手工删 `layout-v2` 或 `.complete` 来强制重跑。

回滚只适用于有旧版代码且服务停止的情况：先备份当前 `.data`，使用旧版代码在全新数据目录恢复 legacy-v1 的数据库和密钥。直接将旧库覆盖新目录会丢失迁移后记录，因此不建议日常回滚。

## 验证与故障

`npm test` 使用临时目录和本地模拟论坛，不接触真实登录态。出现 needs_login：打开该任务登录窗口并保存；needs_human：人工处理验证；unknown：先查看网站实际结果，再确认是否重试。运行记录不保存密码、Cookie 正文或网页截图。
