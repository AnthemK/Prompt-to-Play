# 隐私存放与禁止上传规则

所有真实账号相关内容统一存放于私有目录 `.data/`：

- `accounts/<account>/`：加密配置、登录态、数据库、独立密钥。
- `evidence/<site>/`：真实页面截图、需要保留的私有诊断材料。
- `backups/`：数据库和密钥备份，仍视为敏感数据。
- `service.log`：可能包含本地管理访问令牌，不分享。

`sites/`、`examples/`、`docs/` 仅存无凭据模板、公开网址和不含个人账号信息的说明。`.test-output/` 只放模拟站点测试产物，也忽略提交。

## 防护层

1. 根目录和项目 `.gitignore` 排除私有目录；项目另排除密钥、数据库、环境变量文件、日志、会话导出及压缩包等。
2. 本机 Git pre-commit 检查**暂存快照**，强制添加敏感路径仍会被拒绝。
3. 本机 Git pre-push 检查该项目的所有本地引用历史，防止凭据从当前文件删除后仍留在旧提交中。
4. `AGENTS.md` 规定未来修改、提交和推送必须遵守本规则。检查器仅输出路径和原因，不输出秘密内容。

手动检查：`python3 scripts/privacy-check.py`；推送前：`python3 scripts/privacy-check.py --history`。测试检查器：`python3 -m unittest discover -s test -p 'test_privacy.py'`。

Git 钩子在本机 `.git/hooks/`，不会随克隆自动安装；其他机器需运行 `python3 scripts/install-privacy-hooks.py` 重新安装。钩子由 Python 3 执行，不依赖签到后台服务。

## 边界

忽略规则和钩子防止误提交，不是操作系统级上传禁令。`--no-verify`、改动钩子、手工上传、云同步或第三方软件都可能绕过；禁止这样操作。文字扫描也不能识别所有个人信息，新文档仍需审阅。不要分享整个项目或其压缩包。

若已提交真实秘密：立刻停止推送，先撤销或轮换相应凭据，再清理 Git 历史；仅添加 .gitignore 或删除最新文件不够。如果已经推送，视作泄露处理。

论坛登录本身仍需把认证数据通过 HTTPS 发送给目标网站；“禁止上传”在此指禁止进入代码仓库、附件、云端备份或无关服务，不阻止已授权的网站认证。
