# 目录与隔离边界

```text
forum-task-runner/
├── src/                    通用服务、调度、浏览器执行与存储
├── public/                 本地管理页
├── sites/<站点>/           站点说明和无凭据任务模板
│   └── sjmc/
├── examples/task.json      新任务的通用示例
├── docs/                   架构、接入、运维说明
│   └── research/           原始调研材料（历史记录）
├── test/                   本地模拟站点与自动测试
├── scripts/                安装与系统自启动脚本
├── .data/                  私有运行数据，不进 Git
│   ├── accounts/<账号ID>/  独立 tasks.sqlite 和独立 vault.key
│   ├── backups/            迁移前数据，敏感，不进 Git
│   ├── layout-v2           存储格式标记
│   └── service.*           共享服务锁、日志
└── .test-output/           本地测试截图，不进 Git
```

## 三个不同概念

- **站点目录**：例如 `sites/sjmc`，存放可分享的接入知识，不存登录信息。
- **账号 ID**：例如 `sjmc`，是运行数据的隔离边界。不同站点必须使用不同账号 ID；同站多账号也分别命名，如 `sjmc-work`。
- **任务 ID**：例如 `sjmc-checkin`，全局唯一；同账号可有签到、领奖等多个任务，共享该账号登录态，但分别记录周期与执行结果。

每个账号有独立数据库、随机生成的加密密钥、登录态和运行历史。程序每次运行创建独立浏览器上下文，按任务 origins 限制请求。相同账号的多任务必须使用相同来源列表。禁止直接修改已有任务的账号归属，以免数据与历史错配；需要迁移或创建新任务。

服务和管理页仍然是共享的，能读取所有账号；这不是操作系统用户级隔离，也不能防御本机管理员或已控制该进程的程序。一个账号数据库损坏仍可能影响服务启动，不宣称故障完全隔离。

## 配置来源

`sites/*/task.template.json` 是可复用模板，默认暂停，**不是实时配置文件**。管理页保存后，实际配置加密写入对应账号数据库。修改模板不会修改正在运行的计划；修改管理页不会回写模板。

`src/store.js` 负责账号路由和旧数据迁移；`src/vault-store.js` 负责单账号 SQLite 和 AES-256-GCM。启动恢复未完成运行时将其标为结果未知，不自动重做提交。
